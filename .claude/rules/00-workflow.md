# 工作流程規則（永遠套用）

## 什麼時候必須停下來問
遇到下列任一情況，**停止實作**，用條列寫出：問題、你看到的事實、2–3 個選項與你的建議，然後等回答。
- 規格沒寫到、或 PRD / ARCHITECTURE / ALGORITHMS 互相矛盾
- 問題列在 `docs/OPEN_QUESTIONS.md`
- 需要加第三方套件、提高最低 iOS 版本、加網路功能、加權限
- 需要改 `docs/ALGORITHMS.md` 的公式或預設參數（調參數要附測試結果說明）
- 要做的事屬於 ROADMAP「後續版本」
- 要刪除或大幅改寫既有的、已通過測試的程式
- 同一個建置或測試錯誤嘗試修 3 次仍失敗
- 需要使用者在 Xcode 介面操作、或在實機上驗證

停下來前，確保程式仍可編譯（未完成的部分可以先不接上）。

## 每個步驟的節奏
1. 讀 ROADMAP 找到目前項目，讀相關文件。
2. 用 3–6 行說明打算怎麼做、會動到哪些檔案。範圍超過一個 ROADMAP 項目時先確認。
3. 先寫或更新測試 → 實作 → 跑測試與建置。
4. 更新文件（ROADMAP 勾選、DECISIONS、ALGORITHMS）。
5. 回報：做了什麼、怎麼驗證（貼出測試結果摘要）、下一步、需要使用者做的事。

## 誠實回報
- 沒跑過的測試不能說通過。沒辦法跑（例如需要實機）就明講。
- 不要為了讓測試通過而放寬斷言或刪測試；若認為測試本身錯了，說明理由並詢問。
- 不要假造測試資料當成真實影片結果。
